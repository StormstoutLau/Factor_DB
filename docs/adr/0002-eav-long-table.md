# ADR-0002: 因子数据采用 EAV 长表模型

- **状态**: 已接受（后被 ADR-0004 修订）
- **日期**: 2026-06

## 背景
因子数据需要存储 100+ 个因子，每个因子在每只股票、每个交易日有一个值。需要设计表结构。

## 决策
采用 **EAV（实体-属性-值）长表模型**，即 `factor_data(trade_date, stock_code, factor_name, factor_value, loaded_at)`。

## 理由
- 因子数量动态增长，长表无需 `ALTER TABLE` 即可添加新因子
- 查询单因子时 `WHERE factor_name = 'X'` 直接过滤
- 早期因子数量少（<20），长表简单直观

## 备选方案
- **宽表**（每因子一列）：因子多时列数爆炸，且动态添加列需 ALTER

## 后果
- ✅ 动态添加因子零成本
- ⚠️ 行数 = 因子数 × 股票数 × 交易日数，膨胀严重（241 因子 = 16.8 亿行）
- ⚠️ `factor_name` 为 VARCHAR，EAV 导致 ART 索引内存膨胀 80 倍（见 ADR-0004）
- ⚠️ 跨因子查询需多次 UNPIVOT/PIVOT，性能差
- **修订**: 见 ADR-0004，迁移到双轨架构
